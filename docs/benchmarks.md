# 性能与一致性测试报告

本文档记录 **小众点评 (xzdp-go)** 在本机真实 PostGIS 与 Redis 环境下的压测结果与复现方法，原始 JSON 数据保存在 [benchmarks-raw.json](benchmarks-raw.json)。

## 测试环境

- **硬件与系统**：Apple M4、macOS arm64（`darwin/arm64`）
- **运行时与中间件**：Go 1.27.3、PostgreSQL 17.6、PostGIS 3.5.3、Redis 8.8.4
- **测试范围**：本机直接调用服务层连接单个 Redis 实例与单个 PostGIS 实例。秒杀吞吐统计的是 Redis 受理阶段；端到端耗时包含重复下单重试、异步写库以及崩溃消息接管。

## 一、商铺多级缓存与击穿保护

测试同一热门商铺在 3 种场景下的表现：进程内 L1 缓存命中（64 并发 5,000 次）、清空 L1 仅命中 Redis（64 并发 5,000 次）、清空 L1 与 Redis 后 200 个并发请求同时冷读。

| 场景 | 并发 / 请求数 | 吞吐 | P50 / P99 延迟 | 实际回源数据库次数 |
|---|---:|---:|---:|---:|
| L1 进程内 LRU 命中 | 64 / 5,000 | **4,003,738 QPS** | 0.0004 / 0.29 ms | **0** |
| L2 Redis 命中 | 64 / 5,000 | **29,781 QPS** | 1.74 / 9.16 ms | **0** |
| 200 并发同时冷读（防击穿） | 200 / 200 | **122,665 QPS** | 1.24 / 1.54 ms | **1**（`singleflight` 合并） |

## 二、高并发秒杀与 Redis Streams 崩溃接管

200 个并发用户同时争抢 100 张秒杀券（同时混入重复请求校验一人一单），并刻意让一个消费者拉取 10 条消息后不确认以模拟进程崩溃，验证 `XAUTOCLAIM` 接管与最终落库一致性。

| 模式 | 受理吞吐 | 受理 P50 / P99 | 落库订单 | 超卖 / 重复 / 丢单 | 崩溃消息接管 | 端到端完成耗时 |
|---|---:|---:|---:|---:|---:|---:|
| 单桶（`STOCK_BUCKETS=1`） | **37,068 QPS** | 4.14 / 4.69 ms | **100 / 100** | **0 / 0 / 0** | **10 / 10** | 390 ms |
| 八桶（`STOCK_BUCKETS=8`） | **30,659 QPS** | 3.65 / 5.97 ms | **100 / 100** | **0 / 0 / 0** | **10 / 10** | 504 ms |

> 说明：在单节点 Redis 上，单桶脚本无需跨桶循环，因此本机单实例压测中单桶吞吐略高于八桶；分桶模式的价值在于多节点或高冲突热点券场景下把库存拆分到多个键，降低单个键的争用。两种模式下剩余库存均为 0，未确认 Pending 队列均清空为 0。

## 三、PostGIS 附近商铺空间索引检索

向 PostgreSQL 批量写入 10,000 家带经纬度坐标的商铺后，以 20 并发执行 500 次带关键词过滤与 `ST_DWithin` 距离排序的附近搜索。

| 指标 | 实测结果 |
|---|---|
| 商铺数据量 | 10,000 家 |
| 并发 / 请求数 | 20 / 500 |
| 吞吐 | **1,767 QPS** |
| 延迟 P50 / P99 | **8.55 ms / 62.64 ms** |

## 复现命令

启动 PostGIS 和 Redis 后，配置 `DATABASE_URL` 和 `REDIS_URL` 并运行：

```sh
make bench
```
